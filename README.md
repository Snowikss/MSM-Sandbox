# MSM Sandbox

Локальная тестовая песочница для экспериментов с серверной логикой в стиле My Singing Monsters.

> Проект предназначен для локальной/частной тестовой среды. Он не подключается к официальным серверам Big Blue Bubble, не использует основной игровой аккаунт и не предназначен для обхода защиты официального сервиса.

## Что уже работает

- тестовый профиль;
- Plant Island;
- монеты, алмазы и еда;
- добавление и удаление тестовых монстров;
- изменение уровня монстра;
- режимы таймеров `x1`, `x10`, `instant`;
- сохранение состояния в `data/state.json`;
- веб-панель администратора;
- локальные auth/pregame endpoints для отдельного тестового клиента;
- WebSocket endpoint `/msm/socket`;
- запись последних HTTP/WebSocket событий для исследования совместимости.

## Запуск на Windows

Самый простой вариант: запустить `start.bat`.

Скрипт проверит Python 3.11, создаст `.venv`, установит зависимости и запустит сервер на всех локальных интерфейсах.

После запуска в окне будут показаны адреса:

- панель на ПК: `http://127.0.0.1:8000/`;
- Swagger: `http://127.0.0.1:8000/docs`;
- журнал клиентских запросов: `http://127.0.0.1:8000/api/compat/logs`;
- адрес для телефона в локальной сети: `http://<LAN-IP-ПК>:8000/`;
- WebSocket: `ws://<LAN-IP-ПК>:8000/msm/socket`.

ПК и телефон должны находиться в одной локальной сети. Если Windows Firewall спросит про доступ Python, разрешите частные сети.

## Compatibility bridge

Bridge сейчас реализует безопасный диагностический минимум:

- `/auth/api/token`;
- `/auth/api/anon_account`;
- `/auth/api/login`;
- `/auth/api/game_config`;
- `/pregame_setup.php`;
- `/msm/socket`;
- `/api/compat/player`;
- `/api/compat/status`;
- `/api/compat/logs`.

Текстовые WebSocket-команды `ping`, `playerSync` и `gameConfig` уже получают ответы. Неизвестные бинарные кадры не подделываются: сервер записывает их размер и начало payload в журнал. Это сделано специально, чтобы следующий слой протокола реализовывался по фактическим запросам тестового клиента, а не наугад.
